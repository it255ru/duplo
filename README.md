# duplo

duplo созвучно со словом «дупло» (укромное место, где что-то спрятано) и с английским duplicate.

CLI-утилита для поиска дубликатов файлов и каталогов и удаления лишних копий.

Документ соответствует версии 0.3.1 (коммит `488ace3`).

## Как это работает

Удаление устроено по схеме plan / apply:

1. Файловая система сканируется один раз, результат сохраняется как снимок.
2. По снимку строится план удаления. План проверяется: в каждой группе
   дубликатов должна остаться хотя бы одна копия. Если план нарушает это
   условие, ничего не удаляется и утилита завершается с кодом 2.
3. Перед удалением каждый файл повторно сверяется с файловой системой.
   Шаг с любым расхождением пропускается, файл не удаляется.

Без флагов `--interactive` и `--auto-first` утилита только анализирует
каталог и ничего не меняет.

## Возможности

- Поиск дубликатов файлов: файлы группируются по размеру, затем
  сравниваются по хешу BLAKE2b.
- Статистика по категориям, расширениям и каталогам.
- Поиск идентичных каталогов без подкаталогов.
- Классификация по расширению: images, videos, audio, documents, archives,
  executables, scripts, data, system, fonts, design, other.
- Кэш хешей в JSON для повторных запусков.
- Интерактивный или автоматический выбор копий, режим `--dry-run`.

## Требования

- Python 3.11 или новее.
- Внешних зависимостей нет, используется только стандартная библиотека.
  Файл `req.txt` (с `termcolor`) устарел, код его не использует.
- Права на чтение сканируемого каталога. Для удаления нужны права на запись.

## Установка

```bash
git clone https://github.com/it255ru/duplo.git

```

## Использование

Анализ без удаления:

```bash
python main.py /path/to/dir
```

Группировка дубликатов по категориям:

```bash
python main.py /path/to/dir --group-by-category
```

Поиск идентичных каталогов (только отчёт):

```bash
python main.py /path/to/dir --find-identical-dirs
```

Проверка плана без удаления. Подтверждение не запрашивается, каждый шаг
проверяется так же, как при реальном удалении:

```bash
python main.py /path/to/dir --auto-first --dry-run
```

Интерактивное удаление:

```bash
python main.py /path/to/dir --interactive
```

Для каждой группы показывается меню:

| Ответ | Действие |
|---|---|
| `s` | пропустить группу |
| `a` | оставить первую копию |
| `b` | оставить последнюю копию |
| `m` | ввести номера сохраняемых копий (`1 3` или `1,3`); неверный ввод переспрашивается |
| `A` | оставить первую копию в этой и во всех оставшихся группах |

Файлы и каталоги выбираются по отдельности. `A`, выбранный для файлов, на
каталоги не распространяется.

Автоматическое удаление всех копий, кроме первой. «Первая» означает первую
по отсортированному пути, а не по порядку обхода файловой системы:

```bash
python main.py /path/to/dir --auto-first
```

`--interactive` и `--auto-first` взаимоисключающие. Перед фактическим
удалением выводится план: первые 20 файлов, у каждого указана сохраняемая
копия, и все каталоги. Затем запрашивается подтверждение `y/n`. Если stdin
закрыт, это считается отказом.

## Аргументы

| Аргумент | Описание | По умолчанию |
|---|---|---|
| `source_dir` | Каталог для анализа | обязательный |
| `--cache-file PATH` | Файл кэша хешей (JSON) | см. «Кэш хешей» |
| `--no-cache` | Не читать и не записывать кэш | выключено |
| `--group-by-category` | Группировать дубликаты по категориям | выключено |
| `--find-identical-dirs` | Искать идентичные каталоги без подкаталогов | выключено |
| `--interactive` | Интерактивный выбор копий для удаления | выключено |
| `--auto-first` | Оставить первую по пути копию в каждой группе | выключено |
| `--dry-run` | Показать и проверить план без удаления | выключено |
| `--version` | Показать версию | |

`--dry-run` действует только вместе с `--interactive` или `--auto-first`.

## Коды возврата

| Код | Значение |
|---|---|
| 0 | Успех, в том числе «нечего удалять» и отменённое удаление |
| 1 | Хотя бы один шаг удаления не выполнен |
| 2 | Неверный ввод: каталог не найден, неизвестный аргумент, план нарушает инвариант, stdin закрыт во время интерактивного выбора |
| 130 | Прервано пользователем (Ctrl+C) |

## Алгоритм

1. Каталог рекурсивно обходится через `os.walk` без перехода по симлинкам.
   Для каждого файла выполняется `lstat` и запоминаются путь, размер,
   mtime (нс), устройство и inode. Симлинки, FIFO, сокеты и устройства
   пропускаются. Ошибки обхода и чтения собираются и выводятся в конце
   отчёта (первые 20).
2. Пустые файлы не считаются дубликатами. Hardlink'и на один inode
   схлопываются в одну запись, потому что удаление одного из них не
   освобождает место. Исключение: файловые системы, где `st_ino == 0`.
3. Файлы группируются по размеру. Файлы с уникальным размером дальше не
   обрабатываются.
4. Для кандидатов вычисляется BLAKE2b. Если в кэше есть запись с тем же
   путём, размером, mtime и inode, хеш берётся из кэша. Группы с
   одинаковым хешем считаются дубликатами.
5. С `--find-identical-dirs` идентичным может быть только каталог, который
   не содержит подкаталогов и необычных объектов и в котором каждый файл
   входит в какую-либо группу дубликатов. Каталоги с одинаковым набором
   хешей объединяются в группу.
6. Перед удалением каждого файла проверяется следующее:
   - каталог-родитель резолвится в тот же путь, что при построении плана;
   - файл по-прежнему обычный, его размер и mtime не изменились;
   - сохраняемая копия существует, является обычным файлом и не тем же
     inode;
   - содержимое файла побайтово совпадает с сохраняемой копией.
7. Каталог удаляется только через `os.rmdir` после удаления его файлов,
   то есть только если он пуст. Рекурсивного удаления нет.

## Кэш хешей

- Linux и macOS: `$XDG_CACHE_HOME/duplo/hash_cache.json`, а если
  переменная не задана — `~/.cache/duplo/hash_cache.json`.
- Windows: `%LOCALAPPDATA%\duplo\hash_cache.json`.

Кэш записывается атомарно, с правами 0600. Повреждённый или нечитаемый
кэш игнорируется с предупреждением. Кэш нужен только для ускорения: перед
удалением файлы всё равно сравниваются побайтово. Старые файлы
`hash_cache.pkl` из версий до 0.3.0 не читаются.

escape-последовательность, утилита не падает.

## Известные ограничения

- `--auto-first` или `[A]` вместе с `--find-identical-dirs` отказывается
  строить план (код 2, ничего не удаляется), если имя одного идентичного
  каталога является префиксом имени другого, например `photos` и
  `photos copy`. Файлы и каталоги сортируются по-разному, поэтому план
  пытается удалить обе копии. Обходной путь: запустить без
  `--find-identical-dirs` или выбрать копии вручную.
- Между последней проверкой и самим удалением остаётся небольшое окно
  (TOCTOU). Не запускайте удаление на дереве, которое одновременно
  изменяют другие процессы или пользователи.
- Идентичными считаются только каталоги без подкаталогов. Деревья
  каталогов целиком не сравниваются.
- Если у удаляемого файла есть hardlink вне сканируемого дерева, место не
  освобождается, но в отчёте объём учитывается как освобождённый.
- Симлинки на каталоги пропускаются, но не попадают в счётчик пропущенных
  объектов.
- В Windows файл с атрибутом read-only не удаляется: шаг завершается
  ошибкой, остальные шаги выполняются.
